Native-agent defect · 5 October 2026

Same bytes.
Different agent context.

Pi changed a command's text depending on where its output arrived in chunks. We reproduced the defect in the official binary and traced it to ANSI color stripping inside Pi.

Expected plain text

ERROR: file.py:1

The colored command output, with color controls removed.

Retained by Pi after a split reset

ERROR: file.py:1m

The final color-reset character became part of the message.

Verified path: user ! commands / RPC bash. This is a native stream-processing defect; downstream model behavior was not measured.

01 / Experiment

Change the delivery boundary. Keep the bytes identical.

We supplied the same colored line to unmodified Pi 1.0.1 on Linux, changing only where its writes were split. Each fresh process ran two controls and four deliberately selected split variants. We repeated this in three fresh native RPC processes, offline, with no extensions, credentials or model calls.

ESC[31mERROR: file.py:1ESC[0m\n

Both controls passed in every process. All four selected split variants corrupted both the live stream and returned output in every process. In the third process, get_messages confirmed the same corruption in Pi's retained bashExecution messages.

02 / Problem

A color code became ordinary text.

Pi already preserved UTF-8 decoder state between output chunks. But it applied stripAnsi() independently to each decoded chunk. If an escape sequence was split, its prefix was stripped or sanitized before its suffix arrived. That suffix then passed through as text.

Chunk A ends:   ERROR: file.py:1 ESC[0
Chunk B starts: m\n
Old result:    ERROR: file.py:1m\n

The affected code is Pi's native bash executor. Its message conversion includes retained user-command output in model context. We verified retention; we did not make a model request to measure its response.

03 / Proposed fix

Preserve escape-sequence state across chunks.

The proposed Pi patch keeps a small parser state between chunks. It strips split CSI color controls and OSC hyperlink sequences before output reaches the live callback, returned result and full-output log. It does not accumulate arbitrarily long control payloads; unfinished sequences are discarded when execution ends.

On source revision 8c911797c3b6b5d3b3921ce4d2438e98e1a948a6 (package version 1.0.3), the initial regression suite passed 1 test and failed 13 before the patch. After the patch, all 14 passed, alongside the 5 existing ANSI utility tests. The cases cover every byte boundary of the selected strings, single-byte chunks, UTF-8, cancellation and full-output files.

Native before/after confirmation: we then ran the original six-case RPC probe against the current source, first unchanged and then patched, in a container with networking disabled. Before: both controls passed and all four split variants failed. After: all six returned, streamed and retained outputs matched the expected text. This is one fresh process per condition, on inspected development cases.

04 / Why Agent Eval Flow

Keep the evidence needed to investigate a failure.

The earlier Pi/OpenCode research used Agent Eval Flow to retain and regrade workflow evidence. This follow-up asked a narrower question: does the agent receive the same text the command produced?

The component probes here are direct native RPC tests. They do not call Agent Eval Flow or an LLM. They establish a defect in Pi, and the proposed source fix belongs in Pi. Agent Eval Flow's role is the surrounding evidence-led evaluation workflow; this was not an automatic bug detection feature of the library.

An exit code of zero did not establish output fidelity. Comparing command inputs, streaming events, returned text and retained messages made this failure observable.

05 / Reproduce and inspect

Evidence you can check without a model.

Run the official binary in a clean offline environment with pi --offline --mode rpc --no-session --no-extensions. Send this single JSON line, then inspect the response:

{"id":"ansi-reset","type":"bash","command":"python -c 'import os,time; os.write(1,b\"\\x1b[31mERROR: file.py:1\\x1b[0\"); time.sleep(0.15); os.write(1,b\"m\\n\")'"}

The expected plain text is ERROR: file.py:1\n. The released 1.0.1 binary returned ERROR: file.py:1m\n. Timing makes this an OS-level reproduction; the deterministic regression tests control delivered chunks directly.

06 / Other results and limits

The null results remain part of the record.

A separate direct-native investigation follow-up completed 12 one-turn runs: 4 on inspected Django/sklearn development cases, and 8 on four frozen, inference-unused NetworkX issue families. Pi 0.99.1 and OpenCode 1.18.33 used Sol 5.6 low, fresh sessions and the original 600-second limit. It found zero net source edits and zero parsed edit-tool attempts. Earlier observed editing violations did not recur in these runs.

Task inputs, original source snapshots and scoring rules were frozen before the NetworkX inference. Hidden checks and future fixes were kept out of agent environments. Hash comparison cannot detect every transient write; public-source training contamination is unknown. These inspected cases cannot serve as an untouched holdout for further tuning.

Separately, six UTF-8 boundary controls passed. We also replicated the already-reported Pi truncation defect #10164 in versions 0.99.1 and 1.0.1: four selected large-output cases failed per version, while two controls passed. We do not claim that existing finding as ours. The ANSI defect is distinct from both that truncation issue and the earlier UTF-8 fix.

  • No model response or coding-accuracy improvement was measured.
  • No causal link to failures in the earlier coding benchmark was established.
  • Selected ANSI component probes are development cases, not a frozen holdout.
  • A bounded duplicate search is not proof of novelty.
  • Raw model traces from the separate investigation study are not published here.

The original coding experiment and its frozen records remain unchanged. This report exports only the benign no-model ANSI captures; the separate investigation outcomes are curated summaries whose private raw model traces are not redistributed.
